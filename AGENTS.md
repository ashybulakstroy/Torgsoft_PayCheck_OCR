# Правила работы в проекте

## Ручные сопоставления

- Хранить знания ручных сопоставлений в читаемых текстовых JSON-файлах. Не использовать SQL-хранилища.
- При поиске знаний игнорировать регистр и любые пробельные символы, в том числе наличие/отсутствие пробелов внутри названия. Исходный OCR сохранять без изменений.

## Обязательное виртуальное окружение Python

- Всегда использовать проектное окружение `.venv` для запуска Python, OCR, скриптов, тестов и установки зависимостей.
- В PowerShell вызывать интерпретатор явно: `& .\.venv\Scripts\python.exe ...`.
- Устанавливать зависимости только через `& .\.venv\Scripts\python.exe -m pip ...`.
- Запускать тесты через `& .\.venv\Scripts\python.exe -m pytest ...`.
- Не использовать глобальные `python`, `pip` или `pytest` и не устанавливать зависимости в системное окружение.
- Если `.venv` отсутствует или неисправно, сначала восстановить проектное окружение; не переключаться молча на системный Python.

## Границы ячеек НДС

- «НДС 16 %», «НДС» и их распознанные варианты вроде `HDC` означают отдельную ячейку/строку таблицы.
- Разделять её до сопоставления товаров со справочником. Числа из столбцов этой строки должны оставаться при НДС, а не переноситься в соседний товар или отдельную пустую строку.
- Последняя печатная строка названия предыдущего товара (например, `CT15074` или `50951`) остаётся частью этого товара, даже если приблизительная граница по центрам цен прошла через неё.
- Сырой OCR не исправлять: корректируется группировка исходных блоков по ячейкам.

## Правила для экспериментов с изображениями и OCR

- Для любых экспериментов, затрагивающих изображения, геометрию, OCR или сегментацию, создавать отдельный файл/модуль, а не вносить хаотичные правки в основной код.
- Диск `R:` — RAM-диск, содержимое теряется после перезагрузки. Использовать его только для временных файлов. Кеш OCR хранить в `.cache/ocr_baselines`, отчёты и сравнения — в `reports/ocr_regression`, прочие сохраняемые экспериментальные артефакты — в `experiment_outputs` на постоянном диске проекта.
- Для признака, затрагивающего изображения или OCR, прогонять проверку на всех фото-файлах набора и выдавать сводку по статистике.
- Минимальная статистика: `files_tested`, `worse`, `better`, `unchanged`, `mean_delta_lines`, `mean_delta_confidence`.
- Если нет абсолютных ухудшений и есть абсолютные улучшения на реальном наборе фото, рекомендовать внедрение в основной модуль приложения.
- Если есть абсолютные ухудшения, либо улучшения не подтверждены на всем наборе, не рекомендовать внедрение в основной код.
- OCR-результат и реальные данные по фото являются решающим сигналом, а не предположения по визуальной оценке.

## Регрессия OCR на истории веб-чеков

- При любом изменении алгоритмов OCR, геометрии, сегментации или группировки ячеек обязательно проверять последние 100 завершённых веб-чеков из `web_outputs`, от новых к старым по `created_at`. Повторные загрузки не исключать.
- Если завершённых чеков меньше 100, проверить все доступные, явно сообщить количество и отметить неполное покрытие. Не выдавать такой прогон за проверку 100 чеков.
- После каждого чека немедленно выводить краткий результат на экран: номер проверки, ID/имя чека, PASS/FAIL, изменения строк/уверенности и причину.
- При первом ухудшении, исключении, отсутствии необходимых артефактов или неподтверждённом изменении данных немедленно остановить прогон, сохранить частичный отчёт и завершить команду с ненулевым кодом. Последующие чеки не обрабатывать; весь прогон считается проваленным.
- Проверять сохранность корректных чисел, товарных строк, НДС и успешной математической проверки. Изменение названий/группировки не считать улучшением без независимого подтверждения исходным фото/эталоном.
- Сравнивать с сохранённым результатом до изменения, не создавать оба результата одним новым алгоритмом. Ручные правки пользователя не считать ошибками исходного OCR: для OCR использовать сохранённые исходные поля и артефакты.
- Для изменений только группировки допустимо повторно использовать сохранённые OCR-блоки, явно указав этот режим. Для изменений OCR-модели, предобработки или геометрии нужен полный повторный прогон из исходного изображения; кеш прежнего OCR не подтверждает такие изменения.
- Отчёты и сравнения сохранять в `reports/ocr_regression` на постоянном диске проекта; долгоживущий кеш — в `.cache/ocr_baselines`. Не оставлять единственный экземпляр важных данных на `R:`. Исходные веб-задания и базу ручных мапингов не менять.
- Использовать общий исполнитель `experiments.web_ocr_regression`; проверка всех фото `data/in_data` дополняет, но не заменяет эту обязательную проверку истории веб-чеков.
- При ошибке, FAIL или неплановой остановке OCR-теста обязательно автоматически создавать визуальный HTML-отчёт: исходное фото, чек/сетка и данные до и после, выделенные изменённые поля, причина остановки и объяснение. Если этап не завершился или артефакт отсутствует, явно показать это вместо выдуманного результата.
- Вывести путь/ссылку на визуальный отчёт в консоль и дать пользователю кликабельную ссылку в ответе. По умолчанию открыть отчёт в системном браузере ОС. При недоступности браузера сообщить об этом и сохранить ссылку; ошибку теста не скрывать. Для автоматических тестов без UI разрешён явный `--no-open-report`.
