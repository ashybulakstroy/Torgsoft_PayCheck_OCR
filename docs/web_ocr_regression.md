# Обязательная регрессия последних 100 веб-чеков

Актуальные постоянные пути: `.cache/ocr_baselines` для кеша и
`reports/ocr_regression` для отчётов. Диск `R:` — RAM-диск; он используется
только для временных файлов и не является основным хранилищем.

Исполнитель: `experiments/web_ocr_regression.py`. Все команды запускаются из
проектного `.venv`. Он выбирает последние 100 завершённых заданий по
`created_at`, от новых к старым, без удаления повторных загрузок. Список ID
фиксируется в начале отчёта. Результаты и новые изображения записываются
отдельно от `web_outputs`.

После каждого чека выводится PASS/FAIL, ID, изменения числа OCR-блоков,
средней уверенности (в шкале 0…1) и причина. Первый отрицательный результат,
неподтверждённое изменение или исключение останавливает весь прогон.
Сохраняется частичный JSON-отчёт.

При FAIL, исключении или прерывании создаётся также автономный
`failure_report.html`: исходное фото, изображения с границами до/после,
таблицы OCR с выделенными изменениями и объяснение причины остановки.
Если эксперимент не завершил этап, отчёт прямо указывает отсутствие
результата. Отчёт встраивает изображения и открывается без веб-сервера.
Ссылка выводится в консоль; CLI по умолчанию открывает системный браузер ОС.
Ошибки запуска браузера не скрывают исходный FAIL.

Для запуска без UI используется явный `--no-open-report`.

Коды завершения: `0` — все 100 проверены; `1` — провал/остановка;
`2` — доступных чеков меньше 100, полное покрытие не достигнуто.
Отсутствующие артефакты не пропускаются. Повреждённый индекс истории
также считается ошибкой, а не поводом тихо уменьшить выборку.

## Изменения группировки

```powershell
& .\.venv\Scripts\python.exe -m experiments.guarded_printed_grid
```

Это повторная группировка сохранённых OCR-блоков, не повторный запуск всей
нейросети. Предыдущие результаты берутся из сохранённых исходных полей
`receipt.json`; подменять их ручными правками и выбранными названиями из
справочника нельзя. Неизвестные изменения названий требуют эталона и
по умолчанию приводят к FAIL, а не к автоматическому «улучшению».

Первый эксперимент сетки и эксперимент количеств также по умолчанию используют
эту историю и тот же fail-fast исполнитель:

```powershell
& .\.venv\Scripts\python.exe -m experiments.printed_grid_segmentation
& .\.venv\Scripts\python.exe -m experiments.evaluate_quantity_cells
```

Историческая дополнительная проверка всех файлов `data/in_data` сохранена
через `--dataset`. Она не заменяет проверку веб-истории.

## Изменения OCR, изображения или геометрии

Нужен полный прогон из исходного `upload.bin`:

```powershell
& .\.venv\Scripts\python.exe -m experiments.web_ocr_regression --candidate experiments.web_ocr_regression:current_pipeline --scope full_pipeline
```

Новый алгоритм проверяется аналогичным адаптером `module:function`, который
возвращает новый чек, новые OCR-блоки и `scope='full_pipeline'`. Исполнитель
не позволяет объявить обычный кешированный адаптер полным прогоном.
Геометрия и OCR запускаются только в новой папке задания, не через живой сервер.

## Оценка

Проверяются строки товаров/доставки/НДС, корректные числа, успешная проверка
суммы и НДС, количество OCR-блоков и уверенность. Это консервативный барьер:
меньшее число блоков не всегда означает худший OCR, но такой случай нельзя
принять без подтверждения. Смысловая корректность названий не определяется
только совпадением итоговой суммы.

Расширяемый адаптер может приложить независимую проверку изменённых данных.
`verified` нельзя устанавливать только потому, что результат нового алгоритма
отличается; для числового восстановления сохраняются отдельные OCR-свидетельства
и проверка печатной суммы. Корректные числовые поля этот общий барьер не разрешает
переписывать даже при таком признаке.

Настоящая успешная проверка на 100 чеках не объявляется до накопления 100
завершённых заданий. Отрицательные результаты не удаляются из выборки.

Тесты самого исполнителя:

```powershell
& .\.venv\Scripts\python.exe -m pytest App/tests/test_web_ocr_regression.py -q
```
