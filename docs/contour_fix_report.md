# Проверка исправления контура — 26.10.2026

Изменён именно детектор границы таблицы. Новый модуль: `App/table_boundary.py`, версия `table-boundary-2.0`.

## Что исправлено

- Оба старых входа детекции используют один наблюдаемый полигон.
- Удалены convex hull, принудительное сокращение до четырёх точек и выдуманные трапеции из bounds.
- Кандидаты получаются из направленной морфологии, адаптивного порога и Canny при нескольких размерах соединения разрывов.
- Выбор учитывает печатную сетку, протяжённость внутренних разделителей, непрерывность границы и вложенные кандидаты. Край бумаги или штрихкод не выигрывают только благодаря размеру.
- Полигон сохраняет изгиб верхней рамки и ступеньку ячейки итога. Незначительные текстовые отростки удаляются морфологическим открытием заполненного полигона; вогнутости не заменяются выпуклой оболочкой.
- Сложный контур не передаётся в гомографию как четыре угла. `rectify_receipt` сохраняет исходник, возвращает `source_polygon`, `source_corners=null`, `method=none`, `status=needs_review`.
- Необнаруженная таблица больше не превращается в успешный warp всей фотографии. Старые функции сохраняют возврат рамки только для совместимости; новый вход и пакетный анализ используют явный статус.

## Воспроизведение и ограничения

```powershell
python -m App.contour_review
python -m App --workers 1
python -m pytest -q -k 'not reference_catalog'
```

Параметры находятся в `BoundaryOptions`; настройки рассчитаны на печатную сетку с четырьмя колонками и ограниченным наклоном. Качество на новых снимках, сильных поворотах, исчезнувшей рамке и других форматах таблиц не гарантируется. Без уверенной сетки возвращается `needs_review`. Автокоррекция четырёх углов, уже существовавшая в прототипе, не заменяет нелинейное выпрямление. OCR-улучшение, интеграция с 1С и приёмка на 50 размеченных фото в этой задаче не выполнялись.
