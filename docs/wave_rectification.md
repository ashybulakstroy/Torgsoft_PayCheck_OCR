# Выпрямление волнистых чеков в рабочем проекте

Волновая коррекция включена в обычную обработку загруженного чека. Код находится в `App/wave_dewarp.py`, выбор метода — в `App/receipt_rectification.py`. `App/web_pipeline.py` вызывает общий `rectify_table`. В рабочем пути нет импортов, файлов настроек, весов или данных из исследовательских папок. Нужны только уже установленные NumPy/OpenCV и проектное `.venv`.

## Выбор метода

1. Готовится прежний результат по контуру (`contour_coons_patch`) или исходный кроп, если контурная карта не прошла проверку.
2. Новый алгоритм находит длинные печатные линии внутри таблицы, оценивает их кривизну и строит гладкие опорные кривые. По горизонтальным и вертикальным опорам формируются обратные координатные карты. Итоговое изображение один раз выбирается из исходных пикселей.
3. Проверяются порядок линий, отсутствие складок карты, допустимое растяжение и повторная прямизна линий после преобразования.
4. Для использования в чеке должны быть подтверждены пять границ четырёх столбцов. При успешной прежней коррекции новый вариант выбирается только при заметном улучшении: горизонтальный изгиб прежнего результата больше 2 px, новый меньше 75% прежнего, улучшение больше 1 px; вертикальная геометрия не должна заметно ухудшаться. Если прежний метод вернул исходный кроп, допускается прошедший проверки волновой вариант.
5. Если этих условий нет, сохраняется прежний результат. Если оба алгоритма не могут подтвердить исправление, используется исходный кроп с предупреждением.

Не требуется включать режим разработчика: алгоритм работает и в обычном режиме. В «Rectify · рабочая таблица» показывается выбранное изображение. При волновой коррекции подпись сообщает: «Выпрямлены волны по внутренней сетке; ячейка итога сохранена». В логах режима разработчика виден этап проверки волн и выбранный результат.

## Совместимость с OCR

При методе `wave_grid` восстановленная сетка передаётся в разбор таблицы: позиции четырёх столбцов и границы строк берутся из подтверждённых печатных линий. Эвристика разбиения по центрам нескольких OCR-цен не создаёт дополнительные строки внутри уже подтверждённой ячейки. Правила выделения НДС сохраняются. Изображение, координаты OCR и обратная карта находятся в одной системе координат.

В `web_outputs/<job_id>/rectification.json` сохраняются:

- `method`: `wave_grid`, `contour_coons_patch` или `original_crop_fallback`;
- `grid_layout`: границы подтверждённой сетки для волнового варианта;
- `wave_assessment`: результат проверки, `selected`, найденные линии, якобиан, сравнение с прежним методом и причина возврата к нему;
- `source_polygon`: исходный наблюдаемый контур.

`rectification_map.npz` содержит итоговые `map_x`, `map_y` в координатах оригинала. В `receipt.json` поле `rectification_method` сообщает выбранный метод. Все артефакты сохраняются в обычном каталоге обработки; старые чеки не переобрабатываются автоматически. Чтобы получить новый результат для прежнего фото, загрузите его ещё раз.

Волновая коррекция исправляет геометрию и не выводит недостающие числа из суммы. Дополнительное чтение пустого количества выполняет отдельный рабочий модуль `App/quantity_cells.py`: только по пикселям своей ячейки, с проверкой двух чтений, итоговой суммы и НДС. Неподтверждённые значения остаются на проверке пользователя. [Описание и статистика](quantity_cells_and_vat.md).

## Запуск и проверки

```powershell
& .\.venv\Scripts\python.exe -m App.web_server --host 0.0.0.0 --port 8023
& .\.venv\Scripts\python.exe -m pytest -q App/tests/test_wave_rectification_core.py App/tests/test_receipt_rectification.py
& .\.venv\Scripts\python.exe -m App.tests.browser_wave_rectification_check
& .\.venv\Scripts\python.exe -m App.tests.browser_web_check
```

В браузерных проверках нужен Microsoft Edge и Playwright из проектного окружения. Сложное фото для регрессии находится в `App/tests/fixtures/wavy_receipt_596753.png`. Проверяются реальная загрузка в веб-сервер, выбранный рабочий метод, две позиции, сохранение итога, обратная карта, рамки ячеек, режим разработчика и восстановление после обновления страницы. Два прежних примера с НДС проверяются отдельным существующим сценарием.
