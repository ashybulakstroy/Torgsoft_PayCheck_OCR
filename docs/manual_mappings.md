# База ручных сопоставлений

Текстовый JSON: `data/knowledge/manual_mappings.json`, UTF-8 с отступами и читаемыми русскими названиями. Создаётся при запуске веб-сервера. SQL не используется. Файл можно открыть обычным текстовым редактором.

Пользователь выбирает товар из справочника и сохраняет/утверждает строку. Сервер проверяет товар, выбранный артикул и ревизию чека, затем сохраняет исходное `name_raw`, ключ и название товара, артикул, время, идентификатор обработки и номер строки. Свободный ввод названия без выбора справочника не создаёт правило. Изменение только цены или количества у уже принятого товара не обучает базу. Выбор кандидата без сохранения тоже не обучает.

Раздел `mappings` содержит актуальное решение для каждого OCR-текста. Повторный выбор другого товара обновляет решение; массив `history` хранит предыдущую и новую версии каждой ручной записи. Оба раздела сохраняются одной атомарной заменой JSON-файла, чтобы читатель не увидел частично записанные данные. Записи из нескольких потоков веб-сервера защищены общей блокировкой. Автоматический матчинг не записывает правила. История прошлых чеков автоматически не импортируется.

Порядок поиска во всём `CatalogMatcher` (веб и пакетная обработка):

1. Выполнить обычный подбор существующим алгоритмом.
2. При результате 100% сохранить обычный результат.
3. При результате меньше 100%, в том числе при отсутствии кандидата, найти тот же исходный OCR-текст в базе ручных сопоставлений.
4. Проверить, что выбранный товар и артикул существуют в текущем справочнике. Применить сохранённый выбор; повторное ручное подтверждение названия не требуется. При неоднозначном названии используется ранее выбранный артикул.
5. Если записи нет, товар удалён или артикул изменился, оставить обычный результат для проверки пользователем.

Ключ приводит Unicode к NFKC, регистр к нижнему и удаляет все пробельные символы, включая пробелы внутри названия, переносы строк и табуляцию. `Пила CT 15074`, `пилаct15074` и `П И Л А CT15074` используют одно знание. Исходный OCR остаётся без изменений. Числа, пунктуация и ошибки OCR не исправляются; строка с другим размером или моделью не наследует правило автоматически. Новые решения и изменения JSON-файла видны при следующем поиске, даже если автоматический результат уже находится в кэше.

Результат содержит `source: manual_mapping`, исходное автоматическое сопоставление в `automatic_match` и ссылочные данные сохранённого решения в `manual_mapping`. Значение `score: 100` для такого результата обозначает точное совпадение с ключом подтверждённого правила, а не текстовое сходство OCR и названия справочника. Исходный OCR и его уверенность остаются неизменными. Служебные поля не выводятся в электронном чеке. Жёлтая подсветка названия снимается, числовая проверка чека продолжает выполняться независимо.

Во время обычного матчинга прогресс обновляется событиями обработанных строк. Справа появляется выбранное название. После обработки автоматическое выделение снимается. При наведении на товар слева остаётся жёлтая рамка без заливки; повторное создание рамок и запуск анимации отключены. Отдельного искусственного ожидания или анимации «поиска по базе» нет. В электронном чеке жёлтым выделяется только ячейка спорного названия; номер, количество и цена не окрашиваются матчингом. На рабочем изображении соответствующая ячейка названия подчёркивается жёлтой линией без заливки. При достижении порога или утверждении пользователем обе отметки снимаются.
