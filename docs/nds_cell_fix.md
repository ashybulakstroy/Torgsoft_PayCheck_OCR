# Отдельная ячейка НДС — 26.10.2026

На двух указанных пользователем снимках приблизительная граница по центрам цен проходила через последнюю строку названия товара. Дополнительное разделение извлекало только текст НДС, оставляя его числа с оторванным артикулом товара.

Исправление в `App/ocr_catalog_eval.py`:

- Перед группировкой блоков граница уточняется по промежутку между последней строкой названия и меткой «НДС» / «НДС 16 %» / `HDC`.
- Одна строка собирается целиком со своими блоками названия, номера, количества и цены. Извлечение только названия НДС больше не создаёт ложную товарную или пустую числовую строку.
- Существующие метки доставки и итога также образуют отдельные ячейки.
- Правила матчинга, порог из `.env`, названия и исходные OCR-файлы не изменялись.

Проверка выполнена по исходным OCR-блокам обоих вариантов — `original_crop` и `rectified`:

| Фото | Последний товар | Отдельная строка НДС |
| --- | --- | --- |
| 2026-10-24 at 13.33.50 | Дисковая Пила CROWN @185 CT15074; значения `1`, `31600T` | `НДС 16 %`; значения `5056`, `1T` |
| 2026-10-25 at 13.16.05 | Вторая дверь заканчивается `50951`; цена `216000 T` | `HDC`; значения `88656`, `1 T` |

На втором снимке остаётся две товарные строки и одна строка НДС. Количество второй двери в сохранённом OCR не распознано; оно не подставляется вручную из фотографии.

Добавлены регрессионные проверки двух реальных снимков в обоих вариантах и четырёх написаний метки НДС. Отчёты пересобираются из сохранённого OCR командой:

```powershell
& .\.venv\Scripts\python.exe -m App.ocr_catalog_eval
```

`--reuse-matches` для применения этого исправления не подходит: он сохраняет старую группировку ячеек.
