# Исправление отображения чека и итога

Проверены резервные архивы в корне проекта: `App.zip`, `App (2).zip`, `App (3).zip`, `App (4).zip`. В `App.zip` веб-файлов нет. JS/HTML/CSS веб-интерфейса в остальных трёх архивах совпадали с рабочими файлами до исправления; восстанавливать весь архив не требовалось. Архивы не изменялись, сравнения сохранены отдельно в `R:/TEMP/ocr_visual_restore`.

Изменения касаются представления и проверки уже распознанных чисел; модели, изображения, геометрия и сегментация не изменены.

- На фото убрана постоянная заливка `low-match`. После завершения обработки автоматическое выделение строки сбрасывается. Наведение на товар сохраняет жёлтую рамку без заливки до выбора другой строки. Низкое сходство продолжает выделяться в таблице электронного чека справа.
- Матчинг окрашивает справа только ячейку названия. Слева у такого названия есть жёлтое подчёркивание без заливки; подтверждение товара или достижение порога снимает обе отметки. Лишний резерв под вертикальную полосу прокрутки у таблицы отключён (`scrollbar-gutter: auto`), поэтому цветной итог заканчивается на правой границе таблицы, без дополнительной полосы справа.
- Строки с `kind: total` не выводятся в товарной таблице, списке редактирования, сетке товарных ячеек и CSV. Они сохраняются в JSON как свидетельство исходного OCR. «Итого» показывается один раз внизу электронного чека.
- Если отдельное поле `total_raw` пусто, но OCR распознал итог в строке `kind: total`, для проверки суммы используется её `price_raw`. Источник записывается как `expected_total_source: ocr_total_row`, с номером строки `expected_total_ocr_row`. Сырой OCR не меняется. Значение, введённое пользователем, не заменяется; сумма не выдумывается из цен товаров.
- При совпадении сумм включается прежний зелёный стиль итога. Наведение на итог подсвечивает всё фото и рабочую таблицу цветом текста суммы. Наведение на товар возвращает рамку строки. Повторной анимации нет.

Для сохранённого чека `49dc382dddaa4cb9a07795b2c107a370` причиной отсутствия зелёного итога был статус `missing_original_total`: `total_raw` был пуст, хотя строка «Корытынды» содержала `642 756,00 T`. После исправления: товары 554100, НДС 88656, сумма 642756, разница 0, статус `match`.

У этого конкретного входного файла есть отдельная особенность: `original.png` — скриншот интерфейса размером 1920×1030. Жёлтые области уже записаны в пикселях загруженного скриншота, что видно при открытии `rectified.png` отдельно от сайта. Их отключение в SVG не изменяет исходную картинку. Для чистого изображения нужен исходный снимок с телефона; автоматическое удаление цветных пикселей в этом исправлении не выполнялось.

Проверки:

```powershell
& .\.venv\Scripts\python.exe -m pytest -q
& .\.venv\Scripts\python.exe -m App.tests.browser_receipt_visualization_check
```

Браузерный сценарий проверяет сохранённый чек, отсутствие дубля итога, зелёную сумму, рамку без заливки, подсветку всего чека по итогу и представление сохранённых OCR-данных для всех 26 фото набора. Изображения и сырые результаты не меняются. Протокол в `R:/TEMP/ocr_visual_restore/visualization_validation.json` содержит `files_tested`, `worse`, `better`, `unchanged`, `mean_delta_lines`, `mean_delta_confidence`. Сравнение относится к представлению; улучшение OCR не заявляется. Отдельно проверены SHA-256 исходных OCR-файлов, изображений и карт проблемного чека.
