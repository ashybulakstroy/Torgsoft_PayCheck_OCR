# Разделение склеенных товарных строк в рабочем приложении

Включено по явному разрешению пользователя 27.10.2026.
Рабочий модуль — `App/row_cell_split.py`; вызывается из
`ReceiptPipeline.process` до восстановления количеств, разделения числовых
ячеек и матчинга. Зависимостей от экспериментальных папок нет.

Условия применения: две независимые пары количества и цены внутри одной
исходной товарной строки; единственная подтверждённая печатная граница
с поддержкой нескольких столбцов и пересечениями; две полноценные позиции
после разделения; сохранность каждого исходного OCR-блока; успешная проверка
суммы и НДС. Сырой OCR не переписывается. Блоки между готовыми соседними
товарами не переносятся. Пересекающий границу OCR-блок означает отказ от
автоматического разделения; отдельное повторное OCR такого блока пока не реализовано.

Пользователь подтвердил полезность контрольного примера с маслом и генератором:
одна объединённая запись восстановлена как две позиции, итог 247780.
Это контролируемая склейка реальных OCR-блоков, а не естественное ухудшение
распознавания; происхождение примера в статистике не подменяется.
Подтверждённый эталон с фото сохранён в `App/tests/fixtures/reviewed_row_split.*`.

Проверки внедрения: 162 автоматических теста прошли; 62 веб-чека — 0 ухудшений,
0 улучшений, 62 без изменений; 26 фото на независимом baseline до внедрения —
0 ухудшений, 0 улучшений, 26 без изменений. Успешный подтверждённый контрольный
пример проверен отдельно и не добавлен к этим наборам. До 100 веб-чеков история
ещё не накоплена; пользователь явно разрешил внедрение с этими результатами.

Диагностика каждой новой обработки сохраняется в `web_outputs/<id>/row_split.json`.
Сообщение о применении отображается в журнале режима разработчика.
Старые завершённые результаты автоматически не переписываются.

Для независимого baseline служебный Python-параметр
`ReceiptPipeline(split_product_rows=False)` выключает только этот новый этап.
В обычном сервере он включён по умолчанию.

## Постоянное хранение

`R:` — RAM-диск, используемый только для временных файлов. Основные пути
определены в `App/artifact_paths.py` относительно каталога проекта:

- `.cache/ocr_baselines` — кеш OCR и контрольные хеши;
- `reports/ocr_regression` — отчёты, изображения сравнения и сведения об ошибках;
- `experiment_outputs` — прочие сохраняемые результаты экспериментов.

Существовавшие кеш и отчёты скопированы с RAM-диска на постоянный диск.
Их исходные экземпляры на `R:` не удалялись. Исторические ссылки с `R:` в
старых документах могут перестать работать после перезагрузки; новые запуски
по умолчанию пишут в постоянные каталоги.

```powershell
& .\.venv\Scripts\python.exe -m experiments.local_row_split
& .\.venv\Scripts\python.exe -m experiments.evaluate_local_row_split --frozen-baseline
& .\.venv\Scripts\python.exe -m pytest App/tests -q
```
