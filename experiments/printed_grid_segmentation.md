# Проверка границ печатной таблицы

Основной код не изменён. Эксперимент: `printed_grid_segmentation.py`.
Артефакты: `R:/TEMP/printed_grid_segmentation/`.

Проблемный пример: задание `7024426dc8e54e90a35ca8e4ccf23853`,
предзаказ 2142701910. Изображение 437×482 пикселя.

## Причина

`App/ocr_catalog_eval.py`, `table_layout`: горизонтальная морфология с
вертикальным допуском 3 пикселя пропускает наклонные печатные линии и принимает
часть штрихов текста за разделители. Исходные найденные границы:
17.5, 156.5, 204.5, 254, 327, 402, 440.5.

`choose_row_boundaries` добавляет разделители по серединам центров цен:
получаются 17.5, 54, 118, 156.5, 204.5, 254, 327, 407, 440.5.
Эти оценки не соответствуют физическим границам строк.
`resolve_boundary_lines` дополнительно переносит пограничные строки по
близости к числовым якорям. Даже после улучшения обнаружения линий эта эвристика
может ошибочно перенести последнюю строку названия к следующему товару.

Это ошибка определения ячеек и группировки OCR, а не смещение SVG из-за CSS.

## Эксперимент

Существующий детектор `wave_dewarp.find_rules` извлекает локальные наклонные
отрезки и аппроксимирует печатные линии кривыми. Текстовый блок относится
к полосе между двумя кривыми в своей координате X. Подтверждённые полосы
разбираются отдельно, без переноса текста к соседу по центру цены.
Исходные тексты, координаты и confidence OCR не меняются.

На проблемном примере восстановлены все шесть товарных названий и отдельный
НДС. `MAXIMUM`, `металла EPA (EN-R1)`, `на СКЕЛЕТ`, `те) (Деш)` остаются
в своих печатных ячейках.

## Полный набор и ограничения

Повторно сгруппирован сохранённый реальный OCR всех 26 фото `data/in_data`.
Это проверка сегментации на тех же распознанных блоках; новый запуск нейросети
не выполнялся. Улучшение/ухудшение оценивается по ячейкам и данным, а не по
внешнему виду линий.

- files_tested: 26
- worse: 2 — 22.10 13:52:58 и 23.10 17:55:11: пропуски линий, объединение товаров
- better: 1 — 23.10 08:19:57: доставка, НДС и итог разделяются правильно
- unchanged: 23 — включая случай перестановки лишней OCR-цифры без исправления ошибки
- mean_delta_lines: 0
- mean_delta_confidence: 0

Точный пример со скриншота проверен дополнительно и улучшен. Его нельзя
автоматически считать улучшением всего набора: геометрия сохранённого задания
может отличаться от последующего прогона исходного фото.

**Внедрение не рекомендуется:** есть реальные ухудшения. Следующий вариант
должен проверять полноту сетки по числовым якорям/числу строк и отвергать
кандидата, объединяющего разные цены. Отдельно требуется убрать ошибочные
штрихи текста из маски и решить привязку блоков на границе кривых. Эти меры
нужно заново проверять на всём наборе, не подбирая решение только под скриншот.

Основание метода: официальное руководство OpenCV по морфологическому
извлечению горизонтальных и вертикальных линий:
https://docs.opencv.org/4.12.0/dd/dd7/tutorial_morph_lines_detection.html

Запуск из корня проекта:

```powershell
& .\.venv\Scripts\python.exe -m experiments.printed_grid_segmentation --dataset
```

Без `--dataset` модуль теперь запускает обязательную fail-fast проверку
последних 100 завершённых веб-чеков. Историческая статистика этого отчёта
не заменяет её; порядок описан в `docs/web_ocr_regression.md`.
