# Повторное исследование определения ячеек

Рабочий алгоритм не менялся. Новый вариант изолирован в
`experiments/guarded_printed_grid.py`. Изображения, сравнения и JSON:
`R:/TEMP/guarded_printed_grid/`.

## Найденные подходы

1. OpenCV: локальные наклонные отрезки, HoughLinesP или LineSegmentDetector,
   затем объединение в линии/кривые. Для текущих чеков у проекта уже есть
   подходящий детектор `wave_dewarp.find_rules`.
   https://docs.opencv.org/4.12.0/dd/d1a/group__imgproc__feature.html
2. PaddleOCR PP-TableMagic/Table Recognition V2 разделяет распознавание текста,
   структуру таблицы и детекцию ячеек; поддерживает отдельные варианты для
   таблиц с линиями и без линий. Может быть отдельным следующим экспериментом;
   здесь модели не устанавливались и не оценивались.
   https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/pipeline_usage/table_recognition_v2.en.md
3. Microsoft Table Transformer: отдельное распознавание структуры таблицы с
   привязкой OCR. На наших фотографиях не проверялся; качество на научных
   документах не доказывает качество на волнистых кассовых чеках.
   https://github.com/microsoft/table-transformer

Выбор локальных кривых с проверкой OCR-свидетельств — инженерный вывод для
этого проекта, а не гарантия из указанных публикаций.

## Отличия второго эксперимента

- Печатная граница задаётся кривой Y(X). Для каждого OCR-блока используется
  её значение в X самого блока. Одна горизонтальная оценка Y для всей строки
  не учитывает наклон.
- Текст группируется внутри физически подтверждённых полос. Последняя строка
  названия не переносится к соседу по близости к центру цены.
- Порядок OCR-строк внутри полосы сохраняется.
- Кандидат отклоняется при изменении числа товарных/служебных строк,
  их типов, потере текстовых блоков, изменении уже распознанных чисел либо
  потере успешной математической проверки.
- Особый проверяемый случай: прежняя «цена НДС» может оказаться суммой итога.
  Это устанавливается по исходному OCR-блоку, который физически лежит ниже
  нижней кривой в своей X-координате. Такое переприсвоение допускается только
  при успешной полной проверке суммы и НДС.
- Недостающие числа не вычисляются из итога; используются существующие
  распознанные блоки соответствующих печатных ячеек.
- При отклонении возвращается прежняя группировка без изменений.

Этот вариант выбирает между прежней и новой сегментацией целиком, а не
достраивает отсутствующие печатные линии. Последнее остаётся отдельной задачей.

## Вывод

На текущем наборе есть подтверждённое улучшение и нет ухудшений. Этот вариант
можно рекомендовать как дополнительную проверяемую ветку с обязательным
возвратом к прежней группировке. Это не доказательство отсутствия ошибок на
новых фотографиях: все дефекты прежнего результата при отклонении остаются.
В основной код ничего не переносилось.

```powershell
& .\.venv\Scripts\python.exe -m experiments.guarded_printed_grid --dataset
```

Актуальный обязательный запуск по умолчанию проверяет последние 100
завершённых веб-чеков с немедленной остановкой при первом FAIL:

```powershell
& .\.venv\Scripts\python.exe -m experiments.guarded_printed_grid
```

Историческая оценка 26 фото выше не заменяет этот барьер. В веб-прогоне
неподтверждённые машинным эталоном изменения названий считаются FAIL,
даже если раньше их вручную рассматривали в исследовательском отчёте.
