# Локальное разделение склеенных товарных строк

После явного разрешения пользователя логика перенесена в `App/row_cell_split.py`
и включена в рабочий pipeline. `experiments/local_row_split.py` — адаптер
регрессионной проверки того же рабочего модуля. Ниже сохранена история исследования;
текущий статус внедрения описан в `docs/row_cell_split.md`.
Внедрённое разделение количества и цены в `App/numeric_cell_split.py`
не изменялось.

## Реализованный проверяемый вариант

- Поиск только внутри существующей товарной строки, без переноса блоков
  между уже существующими соседними товарами.
- Нужны две независимые пары «количество + цена». Переносы названия и длинная
  строка сами по себе не включают алгоритм. Одни номера позиций пока недостаточны.
- Между числовыми парами должна находиться единственная печатная линия:
  проверяется покрытие нескольких столбцов и пересечения с вертикальными
  разделителями количества/цены.
- Если линия пересекает OCR-блок, разделение отклоняется с причиной
  `crossing_ocr_requires_cell_reread`. Повторное распознавание отдельных ячеек
  в этой первой версии не реализовано; текст блока не разрезается наугад.
- После разделения обе позиции должны иметь название и отдельные числовые
  поля; все исходные OCR-блоки должны сохраниться ровно по одному разу.
- Требуется полная проверка печатного итога и НДС. При неоднозначности или
  ошибке сохраняется прежний результат. При принятии новые технические ID строк
  нумеруются последовательно; `source_row` указывает исходную объединённую строку.

## Проверка 27.10.2026

1. Шесть автоматических проверок прошли: подтверждённый разделитель,
   отсутствие разделителя, перенос названия при одной паре чисел, пересечение
   OCR-блока, неверный итог, запрет переноса между готовыми соседними строками.
2. Последние завершённые веб-чеки: files_tested **62**, worse **0**, better **0**,
   unchanged **62**, mean_delta_lines **0**, mean_delta_confidence **0**.
   Нет достаточных признаков естественной склейки — алгоритм не активировался.
   Это проверка невмешательства, а не доказательство успешного исправления.
   Полное покрытие 100 чеков не достигнуто.
3. Контрольная склейка двух позиций реального чека №596753: объединены только
   записи масла и генератора; фото и реальные OCR-блоки сохранены.
   Алгоритм восстановил два названия, количества 1/1, цены 5780/242000 и итог
   247780. Это искусственно созданная ошибка группировки, не естественный
   положительный случай в статистике набора.
4. Проверка всех 26 исходных фото остановлена **до первого сравнения**:
   прежний кеш `R:/TEMP/quantity_cell_recovery` отсутствует. Следующие фото
   не обрабатывались, вместо выдуманных результатов создан отчёт об остановке.

Вывод: полезность разделения на естественно склеенных строках полного набора
не подтверждена. Внедрение этого эксперимента не рекомендуется. Для продолжения
нужно восстановить независимые базовые OCR-артефакты из долговременного архива
либо получить новый документированный baseline до изменения алгоритма.
